# GAWM 旧实验低成功率排查（2026-09-21）

## 结论与边界

B/C 在 117k 都为 63/100，100 个相同场景的成功/失败逐一一致。这支持：在同一模型配置、官方数据、优化配方和 DDP 设置下，当前 starVLA 的训练主循环可以复现 LiLa 训练循环。它不证明旧 DeepSpeed 路径、旧优化超参数或旧数据流程与 C 等价。

本次定位到一个确定的早期输入错误：本地转换视频红蓝通道颠倒，早期主训练未纠正而在线观测按 RGB 输入。后续实验已修复这个错误，仍有闭环失败，因此不能将全部差距归因于颜色。模型输入、视觉配置、数据来源和训练预算还有多个同时变化的因素；目前不能给它们分配因果贡献百分比。

排查只读取历史配置、日志、数据并生成本报告，没有修改 C 或重启 A/B，没有启动新的训练或闭环评测。

## 对齐具体实验，避免混称“旧 GAWM”

| 实验 | 可核实结果 | 范围 |
|---|---|---|
| `gawm_s_robotwin_continuous_next_49tasks_40k_20260905` | 旧主评测日志末条 0/48 | 非完整 100 回合结果；50 任务中的旧 49 任务训练 |

## 1. 确认的错误：早期训练/部署颜色不一致

本次重新解码 `blocks_ranking_rgb` 的 episode 0、20、499 的原始头部视频与转换训练视频首帧。两边均由 PyAV 解为 RGB；直接平均像素差依次为 6.456、6.782、6.935，交换转换视频红蓝通道后降至 1.299、1.289、1.353。

旧 40k 配置没有 `video_channel_order: bgr`；共享 loader 默认 rgb，不交换通道。在线 `model2robotwin_interface.eval()` 将模拟器的 RGB 直接送入模型。因而同一个红块在训练和部署中的颜色表示不一致。历史更广抽样为 49 任务 × 3 段头部视频，147/147 均在交换通道后更接近原始视频；没有据此声称检查了所有视频和所有腕部帧。

后期 `gawm_joint/config.yaml` 已设置 `video_channel_order: bgr`，loader 的含义是把已颠倒的视频交换回来。该后期对照仍只有开发集 3/20，因此修复颜色不是完整解决方案。不可把再次交换在线 RGB 或修改归档配置当成已训练权重的普适修复。

## 2. 确认的信息差异：命令状态与真实末端反馈

本次均匀抽取本地 1000 条中的 20 条轨迹，共 9,445 帧，`observation.state` 与同帧 `action` 最大绝对差为 0。模拟器 `robot.py` 的 `get_left/right_arm_jointState()` 返回 `joint.get_drive_target()`，不是 measured qpos；在线旧接口也读取该字段。因此这里主要是缺少真实反馈，不是已经证明的训练/部署 state 字段错配。

旧 continuous-next 已将标签移动为 t+1..t+16，不能再把它描述成“首个标签直接泄漏”。但序列较平滑：本次样本仅复制当前命令，下一步归一化 L1 的逐轨迹均值就为 0.00470，整段 16 步约 0.0393。旧模型在历史 64 个分层样本上 L1 为 0.00549（该批复制基线为 0.02787）。它确实学到了动作，低离线误差却不能保证识别抓空、推走物体后正确恢复。

B/C 使用 16 维末端位姿与夹爪状态，不再以完整当前关节动作作为状态。真实姿态反馈更适合判断执行偏差，是重要候选原因；尚未完成只改变 state 的闭环对照，不能声称已证明是首要原因。

## 3. 旧版与 B/C 并不是完全相同的模型配置和配方

| 项目 | 旧 49 任务 40k 主实验 | B/C |
|---|---|---|
| DINOv3 | ViT-B/16，可训练，encoder LR 1e-6 | ViT-L/16，冻结 |
| 当前视觉 | 三相机，每视角 224×224 | 头部相机 320×240 |
| 压缩 | 每视角 16 tokens（4×4），三视角共 48 | 单视角 64 tokens（8×8） |
| 状态 | 14 维关节/夹爪命令 | 16 维末端位姿/夹爪 |
| 动作标签/执行 | t+1..t+16；执行 16 | t..t+31；执行 16，B 样条平滑 |
| 世界模型未来 | +6/+12 记录帧 | +16/+32 记录帧 |
| 数据 | 本地生成 clean，49,000 条名义轨迹，训练 46,550 | 作者 clean+randomized，50 任务 27,071 条 |
| 初始化 | 从 GAWM-S-base 160k 权重继续训练 | DINO 预训练，策略随机初始化 |
| 训练预算 | 新增 40k × 全局 192 = 7.68M anchor draws | 117k × 128 = 14.976M；316k 为 40.448M |
| 学习率 | base 3e-5、动作头 1e-4、encoder 1e-6；40k 衰减 | 策略 2e-4；按 1,912,800 步长周期衰减 |
| AdamW | betas=(.9,.95)，WD=1e-8 | betas=(.9,.99)，WD=.01 |
| 归一化/输出 | joint q99、不裁剪；连续夹爪；tanh_linear_tail | 官方 min/max；tanh |

表中的训练量不是唯一帧数，也未将旧 160k 混合预训练计入，因此不能直接称旧模型总训练不足。可以确定的是目标域训练曝光、学习率轨迹和模型容量没有对齐。4×4 与 8×8、B 与 L 的差异可能影响小块定位，但没有做消融就不能宣称某个结构是根因。

本地排序数据的历史全量图像审计还发现前 500 与追加 500 中有 494 对初始场景匹配，30 个验证 episode 与训练场景匹配。这是场景重复证据，不等于 494 对完全相同的动作轨迹。它减少了有效场景多样性，并让离线验证偏乐观；后续单任务实验已经采用修正的 split，不能把该问题套到所有后期实验。

## 4. 已核查但没有发现对应错误的地方

- 对旧 40k 检查点调用真实 `PolicyNormProcessor`，用 episode 999 每 4 帧抽取的 115 个动作做训练变换/部署逆变换，最大误差 6.86e-7。模型顺序是左关节、右关节、左夹爪、右夹爪；接口显式置换到模拟器顺序。不能因夹爪索引与 B/C 不同就认定错位。
- 旧 continuous-next 已使用 `q99_clip=None` 和无硬边界的 `tanh_linear_tail`。更早版本的硬裁剪/二值夹爪问题不能继续算在这个模型头上。
- 旧日志 1k、10k、20k、30k、40k 的 base LR 与 1k warmup + 40k cosine 的理论值一致，最大数值差约 3.4e-21；没有发现该主实验学习率提前跑完。
- 旧主实验日志明确为 DeepSpeed ZeRO-2，梯度累积 8。当前安装的 `DeepSpeedOptimizerWrapper.zero_grad/step` 是空操作，更新由 DeepSpeed backward/engine 管理；不能把普通 Accelerate 路径曾有的 zero_grad 顺序问题直接当作这个实验失败原因。
- 以上检查不等于完成历史 DeepSpeed 的数值等价重演，也不代表旧优化超参数最合适。

## 下一步真正能定位因果的实验

### 补充：任务采样改变进一步放大了训练曝光差距

9 月 21 日再次核查：旧 mixture 的 49 个任务权重均为 1，`balance_dataset_weights=false`，故排序任务抽样概率为 1/49≈2.04%。B/C 按全数据帧洗牌，排序任务占 250,980/6,120,962≈4.10%，约为旧概率的 2.01 倍。按配置估计：

| 训练点 | 全部 anchor draws | 排序任务预期 draws | 相对旧主训练 |
|---|---:|---:|---:|
| 旧 40k、batch 192 | 7,680,000 | 156,735 | 1× |
| B/C 117k、batch 128 | 14,976,000 | 614,066 | 3.92× |
| B/C 316k、batch 128 | 40,448,000 | 1,658,504 | 10.58× |

这些是由采样分布计算的期望值，不是实际逐条读取日志，也不包括旧 160k 预训练和后期单任务微调。该证据提高了训练预算/采样因素的排查优先级，不能用来声称其已解释全部成功率差距。

作者实际保留 2,466 条 clean、24,605 条 randomized；排序任务为 49 clean + 496 randomized。本地曾使用的生成集为纯 clean（旧主训练 49 任务，49,000 条名义轨迹）。另有 `/data/gaoxiang/RoboTwin/{Clean,Randomized}` 三相机数据 27,500 条，不能将它与旧主训练实际使用的 `/data/gaoxiang/RoboTwinGenerated/Clean` 混称为同一份数据。两者来自相同 RoboTwin 任务体系不等于训练分布相同，也不能据此断言作者轨迹质量更好。

为优先检验预算假设，可以在 C 的固定数据/模型/训练器上，用相同全局样本量和旧任务采样权重重现旧预算：40k×192 等价于 batch128 下 60k 步；恢复任务等概率采样后，排序任务预期曝光也匹配。保持较长训练组作对照，然后单独比较采样权重。若仅在 C 按帧采样下取 60k checkpoint，只匹配了总 draws，排序任务仍有约两倍曝光。

以 C 已验证的配置为共同基线，固定官方数据、训练步数、种子和评测种子，从相同 DINO 资产及策略初始化规则开始，独立改变一个因素：

1. **状态**：真实 16 维 endpose 改为原始 HDF5 的 14 维关节命令；训练和部署一起改，不能把 14 维数据硬塞入现有 16 维 checkpoint。
2. **空间压缩**：保持 DINO-L 冻结，只把 64 tokens 改为 16。
3. **视觉编码器**：保持其余项与 C 一致，L 改为 B 并保持冻结；“是否训练编码器”另做一组。
4. **优化配方**：保持 C 数据/模型，只替换旧学习率、调度和 AdamW 参数；若发现退化，再拆成单项。

颜色错误可用同一旧 checkpoint、相同场景、仅切换输入通道补做闭环配对；已有单回合 BGR 筛查仍失败，不能据此估计总体修复收益。上述新实验本次没有启动；当前 C 的 316k 评测按原计划继续。
