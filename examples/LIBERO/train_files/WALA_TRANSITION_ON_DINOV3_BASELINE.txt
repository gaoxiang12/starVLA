WALA-style transition supervision on the DINOv3 LIBERO baseline
================================================================

This experiment starts from the validated checkpoint below instead of the
compact/interleaved model:

  playground/Checkpoints/
    lewm_oft_libero_dinov3b_spatial4x4_trainenc1e6_statecond_ema09_200k_fullstate/
    checkpoints/steps_200000_pytorch_model.pt

Its recorded LIBERO suite success rates are 0.94 / 0.99 / 0.96 / 0.71
(spatial/object/goal/libero10), or 0.90 when the four suites are weighted
equally.

What is added
-------------

The deployed path remains:

  DINOv3 -> 4x4 spatial tokens/view -> future-delta world model
          -> visual-action cross attention -> OFT action head

Training adds an auxiliary path inspired by WALA:

1. A teacher tokenizer observes the current DINO tokens and the true future
   DINO-token residuals, then compresses that observed transition into eight
   transition tokens.
2. A teacher decoder reconstructs the normalized true future residuals.
3. A student resampler predicts the teacher's transition tokens from the
   policy's eight action-query hidden states.

The auxiliary modules are never called by predict_action. The DINO pooler,
world model, and its delta_scale EMA are frozen throughout all auxiliary modes by
default, so the validated latent coordinate system does not drift.

Single-run training
-------------------

The default launcher starts directly from the validated 200k baseline
checkpoint and runs all three objectives together:

  WANDB_MODE=disabled \
    bash examples/LIBERO/train_files/run_lewm_oft_dinov3_wala_transition.sh

This selects TRANSITION_MODE=combined, runs 20k steps, and writes one run named
lewm_oft_dinov3b_wala_transition_combined_from200k.

In every forward:

- the teacher tokenizer/decoder reconstructs the observed future transition;
- the student matches stop-gradient teacher tokens and decodes the transition;
- the original action objective updates the deployed action readout/model.

Teacher tokens are detached before student alignment. The mature DINO visual
coordinate modules remain frozen, while teacher, student, visual action head,
and action model are optimized concurrently.

The legacy teacher, student, and joint modes remain available for controlled
ablations, but they are not required by the default workflow.

Run the normal DINOv3 launcher without TRANSITION_MODE to reproduce the
original off behavior. off does not instantiate the auxiliary modules and
continues updating delta_scale exactly as before.

Losses and isolation
--------------------

- combined: teacher encoder/decoder, student resampler, visual action head, and
  action model are trainable. The objective is the original baseline loss plus
  teacher reconstruction and low-weight student alignment/decoding. DINO,
  spatial pooler, latent world model, and task embedding stay frozen.
- teacher: only teacher encoder/decoder are trainable; the optimized loss is
  transition reconstruction (Smooth L1 plus token cosine distance).
- student: only the student resampler is trainable; action queries are
  detached. It uses teacher-token alignment plus reconstruction through the
  frozen teacher decoder.
- joint: teacher and latent-coordinate modules are frozen. The action head,
  action model, and student resampler receive the original baseline loss plus
  low-weight alignment and reconstruction terms.

The main knobs are TRANSITION_TEACHER_WEIGHT (default 1.0),
TRANSITION_ALIGNMENT_WEIGHT (default 0.005), and TRANSITION_DECODE_WEIGHT
(default 0.05). Compare the final combined checkpoint against the untouched
200k baseline on all four suites.
