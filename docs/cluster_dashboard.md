# 多机训练监控

在项目根目录启动（只需要 Python 3.10+ 和 SSH，不需要安装前端依赖）：

```bash
python scripts/cluster_dashboard.py
```

打开 **http://localhost:6008**。如果通过 VS Code Remote SSH 开发，在“端口”面板转发 `6008`。
也可以从自己的电脑执行 `ssh -N -L 6008:127.0.0.1:6008 <SSH_USER>@<主节点地址>`。
服务默认仅监听本机，退出进程即停止监控，不影响训练。

## 页面功能

- 本机与 `agent.md` 中四台节点的总览，预期 40 张 GPU。
- GPU 利用率、显存、温度、功耗和计算进程 PID，以及 CPU / 系统内存占用。
- 点击机器卡片筛选任务与 GPU 详情；勾选多个任务叠加比较 loss。
- 默认显示全程 loss，也可选择最近 600 / 200 / 50 点；支持指标切换、移动均值、线性 / 对数坐标、悬停数值、任务搜索和状态筛选。
- 每节点独立采集，默认每轮完成后等待 5 秒，单节点默认超时 20 秒。
- 节点离线保留上一次数据并标为过期；汇总只计算在线节点。

## 数据目录与节点

配置在 `scripts/cluster_nodes.json`，可用 `--config <文件>` 指定其他配置。
`paths` 是每台机器上的训练日志目录，`{repo}` 替换为运行服务时的项目绝对路径。
默认扫描 `playground/Checkpoints` 与 `.cache/multinode/runs`；节点可单独设置 `paths`。
每节点展示最近更新的 30 个 `metrics.jsonl`。资源轮询只读取文件尾部最多 2 MiB、最近 600 条记录。
“全程”对勾选的任务按需分块读取整个日志中的 loss / mse / error 指标，浏览器保留完整历史，
后续刷新只传输新增记录；日志轮换或截短时重新加载。加载失败会明确提示，已有曲线会保留。
全程范围是当前任务文件实际记录的步数；续训之前的数据请同时勾选原任务查看，不会自动拼接不同任务。
未完成写入的行会延后读取，非数值和非有限值不会绘制。

不设置 `host` 表示本机。远端通过免密 SSH，将标准库采集代码通过 stdin 传给 `python3` 执行，
不在远端安装文件，不导入 PyTorch，不占用 CUDA 上下文。可设置节点的 `python` 为指定解释器。
`known_hosts` 使用本项目已有的节点公钥记录；换集群时应配置自己已验证的 known_hosts，
或省略该字段使用 SSH 默认文件。采集不自动接受未知主机密钥。

运行参数：`--port 6008 --interval 5 --timeout 20`。接口为 `/api/cluster`、`/api/history` 和 `/api/health`。
暂停按钮仅暂停浏览器刷新，后台采集继续。

## 状态含义

`train.pid` 存活时显示“运行中”；否则参考 `STATUS.complete/failed/stopped/running`。
只存在运行标记但进程已退出时标为“进程已退出”。没有状态证据时显示“状态未知”。
步数达到配置中的 `max_train_steps` 只显示“已达目标步数”，不推断 checkpoint 已保存成功。
PID 文件应由训练启动脚本维护；复制到其他节点的 PID 文件不应作为任务状态依据。

同一分布式训练可能仅 rank 0 写指标，所以其他节点可以有 GPU 占用而没有本地训练曲线。
复制到各节点的日志会分别展示，不把日志数量当作独立训练任务数。
GPU “占用”表示存在计算进程、利用率超过 5% 或显存使用超过 256 MiB，是资源使用提示，
不等价于调度器预约状态。温度达到 85°C 使用黄色提示。

单次训练的已有详细看板仍可使用 `python scripts/training_dashboard.py <run-dir>`。
